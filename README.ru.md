---



## Зачем это

Либо у агента **нет правил** (хаос), либо один **огромный always-on файл** (жрёт токены, половину игнорирует).

Этот набор — середина:


|     |                                                                                 |
| --- | ------------------------------------------------------------------------------- |
| ✅   | Короткое **ядро** — поведение, security, git, «спроси перед установкой пакетов» |
| ✅   | **По области** — фронт / бэк / тесты / стиль подключаются только когда нужно    |
| ✅   | **Доки по запросу** — методологии на диске, не в каждом чате                    |
| ✅   | **Одна установка** — язык + память + docs в ваш проект                          |
| ✅   | **Онбординг** — стек и линтер выбираются с вами, а не угадываются вечно         |


Можно скинуть репозиторий коллегам: поставили → короткий опрос → спокойная работа с агентом.

## Быстрый старт (для коллег)



### 1. Установка в ваш проект

Выберите **один** способ. Подставьте свои пути
(`Cursor-Constitution` = этот репозиторий, `AboutMe` = проект, куда ставите).

#### Вариант A — Windows, двойной клик (без терминала)

1. Откройте `[scripts/install.cmd](scripts/install.cmd)` (двойной клик в проводнике).
2. На вопрос **Target project** вставьте **полный** путь к корню вашего приложения, например `C:\projects\AboutMe`  
   (относительные пути считаются от `scripts\` — лучше абсолютный).  
3. Язык: **↑ / ↓ + Enter** или ввод `ru` / `en`.  

#### Вариант B — PowerShell (Windows)

Откройте **PowerShell** (в Cursor: терминал → выберите `powershell`, либо Windows Terminal).  
**Не** вставляйте эти команды в Git Bash — `&` и `.ps1` работают только в PowerShell.

Интерактивно (спросит target при необходимости, потом меню языка):

```powershell
& "C:\projects\Cursor-Constitution\scripts\install.ps1"
```

Сразу с путём проекта и языком (без вопросов):

```powershell
& "C:\projects\Cursor-Constitution\scripts\install.ps1" -Target "C:\projects\AboutMe" -Locale ru
```

`-Locale` — `ru` или `en`. `-Target` — корень **вашего** проекта (лучше полный путь).

#### Вариант C — Bash / Git Bash / macOS / Linux

Откройте **bash** (Git Bash на Windows или системный терминал на macOS/Linux).  
**Не** вставляйте сюда PowerShell-команду с `& "...\install.ps1"` — bash упадёт с ошибкой.

В Git Bash пути пишутся как `/c/projects/...`, а не `C:\projects\...`.

Интерактивно:

```bash
"/c/projects/Cursor-Constitution/scripts/install.sh"
```

Сразу с путём проекта и языком:

```bash
"/c/projects/Cursor-Constitution/scripts/install.sh" "/c/projects/AboutMe" ru
```

Аргументы: `install.sh <целевой-проект> <ru|en>`.  
На macOS/Linux — обычные Unix-пути, например `$HOME/dev/Cursor-Constitution/scripts/install.sh`.

#### Что появится в вашем проекте

```text
.cursor/rules/…              ← правила агента (English)
.cursor/project-memory/…     ← идеи, KB, уроки (ваш язык)
docs/…                       ← методологии плоско (без docs/ru)
```

> Папки `docs/en` и `docs/ru` живут только **в этом** репозитории (языковые паки),  
> по тому же принципу что `template/.cursor` → `.cursor`.



### 2. Онбординг в Cursor

Откройте проект и напишите:

> пройди onboarding из `.cursor/rules/onboarding.mdc`

Язык уже выбран. Агент подтвердит стек, **какой линтер** (или «никакой»), тесты и git.  
Пакеты **не** ставит без вашего «да».

### 3. Работа

Пишете фичи как обычно. Агент держит конституцию, подтягивает scoped-правила по типу файлов, открывает `docs/` только когда проектирует что-то глубже.

## Как грузится контекст


| Слой          | Где                                            | Когда в чате                |
| ------------- | ---------------------------------------------- | --------------------------- |
| 🟥 Ядро       | `constitution.mdc`, `project/stack.mdc`        | Всегда                      |
| 🟧 По области | `code-style`, `frontend`, `backend`, `testing` | Подходящие файлы (globs)    |
| 🟨 По запросу | `onboarding`, `retrospective`                  | Агент решает по description |
| 🟩 Справочник | `docs/**`                                      | Агент открыл файл           |
| 🟦 Память     | `.cursor/project-memory/`                      | Уроки / KB по делу          |


**Идея токенов:** библиотеку можно растить; always-on держим ~150 строк.

## Как работает линтер (важно)

**Нет** скрытой схемы «мы всем подсунули свой ESLint».


| Что                                     | Роль                                                                                 |
| --------------------------------------- | ------------------------------------------------------------------------------------ |
| `code-style.mdc`                        | **Интенты** — как писать код (кавычки, `eqeqeq`, hooks…)                             |
| Ваш реальный линтер                     | **Enforcement** — то, что уже в проекте, или то, что выберете на онбординге          |
| Онбординг                               | Пишет в `stack.mdc` поле `Lint / format` (Biome / ESLint / oxlint / Ruff / none / …) |
| `docs/methodologies/eslint-baseline.md` | Опциональный старт **только если** выбрали ESLint и одобрили настройку               |
| Агент перед «готово»                    | Гоняет **ваш** `lint` / `build` / тесты (`T-1`); чинит то, что сломал сам            |


Итого:

1. **Пишет код** — следует интентам из правил и `stack.mdc`.
2. **Проверяет** — запускает скрипт линта проекта, если он есть.
3. **Подключает линтер** — только после вашего выбора и «да» (`W-6`). Интенты маппятся в конфиг **выбранного** инструмента; второго тайного линтера нет.

Если выбрали **none** — агент всё равно старается писать по `code-style.mdc`, но машиной это не enforced, пока не добавите инструмент.

## Как расширять в живом проекте

1. Специфика проекта → `.cursor/rules/project/`, не в общую конституцию.
2. Уроки → `project-memory/lessons/`; третий повтор → правило проекта.
3. Новые глубокие темы → `docs/methodologies/`.
4. Always-on не раздувать — проверка:

```powershell
Get-ChildItem -Recurse .cursor\rules -Filter *.mdc |
    Where-Object { (Get-Content $_.FullName) -match '^alwaysApply: true' } |
    ForEach-Object { (Get-Content $_.FullName).Count } |
    Measure-Object -Sum
```
