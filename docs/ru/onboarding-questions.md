# Опросник для запуска правил в проекте

Тот же набор вопросов, что задаёт агент по правилу `onboarding.mdc`, — здесь в виде
списка для человека. Полезно, если хочется заполнить `project/stack.mdc` руками, без
диалога с агентом.

Работает в двух ситуациях:

| Ситуация | Откуда берётся стек |
| --- | --- |
| Уже есть код / манифесты | Агент читает репозиторий и только подтверждает |
| Пустой или почти пустой репозиторий | Варианты из [`stack-catalog.md`](stack-catalog.md) |

## Вопросы

1. **Язык.** На каком языке агент общается и пишет заметки в `project-memory`? Этот же
   ответ задаёт локаль доков (`docs/ru` или `docs/en`). Это **не** запрет на русский (или
   другой) текст в UI/комментариях кода — если нужен отдельный режим, скажите в п. 7.
2. **Тип проекта.** Фронтенд, бэкенд, fullstack, библиотека, CLI, мобильное?
3. **Стек.**
   - Живой проект: что уже видно в манифесте — что поправить?
   - Пустой проект: выбрать из [`stack-catalog.md`](stack-catalog.md) (только группы,
     подходящие к типу из п. 2). «Другое» — всегда ок.
4. **Линтер / форматтер.** Выберите явно: ESLint, Biome, oxlint, Ruff, Prettier, ничего,
   другое. ESLint — один из вариантов, не дефолт.
5. **Тестирование.** Какой раннер и что обязательно перед словом «готово»: тест на каждый
   баг, только бизнес-логика, или пока ничего.
6. **Git.** Модель ветвления, соглашение по коммитам, можно ли агенту коммитить по
   просьбе.
7. **Жёсткие ограничения** и язык UI-текстов (как язык общения / только en / i18n-ключи /
   без правила).

## Что происходит с ответами

| Ответ | Куда попадает |
| --- | --- |
| Язык, стек, команды проверки, ограничения | `.cursor/rules/project/stack.mdc` (загружается всегда, поэтому коротко) |
| Тип проекта | Определяет, какие правила остаются: `frontend.mdc`, `backend.mdc` или оба |
| Договорённости и контекст, не выводимый из кода | `.cursor/project-memory/knowledge-base.md` |
| Идеи и отложенные решения | `.cursor/project-memory/ideas.md`, `tasks.md` |

В пустом проекте опросник **только записывает** выбранный стек. Установку пакетов и
scaffold агент не делает сам — предлагает шаги и ждёт согласия (конституция **W-6**).

Файлы правил остаются на английском специально (дешевле в каждой сессии). Общение и
заметки — на языке из пункта 1. После установки методологии лежат в плоском `docs/`
целевого проекта (папки `docs/en` и `docs/ru` есть только внутри репозитория
Cursor-Constitution как языковые паки).
